# Getting Started

The StarrySky-L4 is a development board aimed at RISC-V SoC learning, embedded prototyping, and peripheral experiments. **The board is equipped with 16 MB SPI Flash, 8 MB PSRAM, and 8 KB EEPROM, as well as USB-to-serial, an HFP-LINK downloader, a four-digit seven-segment display, a temperature and humidity sensor, a buzzer, user buttons, and LEDs**, and it provides an IO expansion header, an SPI TFT screen interface, and an ESP-01S module interface.
For students who have just encountered this board, you can get to know it from three parts: the main controller executes programs, the memory stores firmware and runtime data, and the buttons, display devices, and sensors on the board handle input and output. The computer and the board are connected via Type-C; serial communication and the on-board downloader share this interface, and the LINK switch selects the connection path.



## Chip Introduction
### Hardware Architecture

The board is centered on the **U2 main controller chip**, with peripherals including memory, communication interfaces, input/output devices, and the accompanying power, clock, and reset circuits. **U2 is the main controller that runs user programs; U17 is the CH32V103C8T6 used by the HFP-LINK downloader.** The two chips each perform different tasks, and you need to distinguish them by reference designator when reading the schematic. A reference designator is the number used to identify a component on the schematic and PCB.

| Item                  | Description                                                  |
| :-------------------- | :----------------------------------------------------------- |
| **Main controller chip** | U2, project package name `ECOS_SoC1`, 128 pins in total   |
| **Processor architecture** | RISC-V                                                  |
| **External clock**    | OSC1 provides a 25 MHz clock, OSC4 provides a 12.288 MHz clock |
| **Core selection**    | 5 signals `CORE_SEL_0` to `CORE_SEL_4`, set via the U3 DIP switch |
| **GPIO groups**       | This package exposes 32 GPIO0 pins, 22 GPIO1 pins, and 12 GPIO2 pins, for a total of 66 GPIO pins |
| **Memory connections** | Dedicated Flash signals connect to the on-board SPI Flash; some GPIOs are multiplexed as the PSRAM interface |
| **Serial connections** | A dedicated UART connects to the CP2102; GPIO0_25 and GPIO0_26 can be multiplexed as UART1, connecting to the ESP-01S interface |
| **Reset input**       | `RST_N_I`, main controller pin 128, active low, controlled by the reset supervisory circuit |
| **Power**             | The main controller core uses 1.2 V, and the IO uses 3.3 V |

The GPIO count in the table refers to the number of pins provided by the main controller package, and does not mean that all of these pins are routed to the expansion header. On this board, the U10 expansion header actually breaks out **29 GPIOs**, some of which are shared with on-board devices.

#### Main Controller and Memory

* **SPI Flash path**: The Flash signals of U2 first enter the U14 switch chip, and then connect to the U5 Flash. U14 is used to select whether the main controller or the HFP-LINK accesses this Flash.
* **PSRAM path**: U11 connects to GPIO0_0, GPIO0_2 to GPIO0_5, and GPIO0_7, which serve as the chip select, four data lines, and clock respectively, to expand the runtime data storage space.
* **EEPROM path**: U26 connects to GPIO0_27 and GPIO0_28 via I2C to store a small amount of data such as configuration parameters; the temperature and humidity sensor is also connected to these two lines.

Both Flash and EEPROM retain data after power loss, whereas PSRAM is used for data storage during runtime and its contents are lost after power loss. The detailed uses of the three are described later in "On-Board Storage".

#### Communication and Peripheral Connections

* **Communication with the computer**: The USB data lines of the Type-C connector connect to the CP2102 or the HFP-LINK through the U13 switch chip. When the CP2102 is selected, the computer exchanges data with the main controller through the USB-to-serial link.
* **I2C bus**: SCL is the clock line and SDA is the data line. The AHT20 and AT24C64D share these lines, and the main controller selects the communication target through different device addresses.
* **Display output**: The on-board four-digit seven-segment display is driven by the TM1650; H3 is used to connect an external SPI TFT screen. The two are independent display paths.
* **Basic input and output**: The main controller reads two user buttons, controls two user LEDs, and drives the buzzer through a transistor.
* **Wireless expansion**: H1 is the ESP-01S module interface, connecting UART1 and the 3.3 V power supply. Wireless functionality requires the corresponding module to be connected externally.

#### Clock and Core Selection

The board is fitted with two active crystal oscillators, whose role is to provide a stable external clock for the main controller. An active crystal oscillator can directly output a clock signal, unlike a passive crystal, which only provides a crystal resonator element.

| Component | Frequency  | Main controller signal | Main controller package pin |
| :-------- | :--------- | :--------------------- | :-------------------------- |
| **OSC1**  | 25 MHz     | `OSC_CLK_25M_I`        | 119                         |
| **OSC4**  | 12.288 MHz | `OSC_CLK_12288K_I`     | 116                         |

**25 MHz and 12.288 MHz are the output frequencies of the external crystal oscillators and cannot be directly taken as the processor's operating frequency.** The clock actually used by the processor is determined by the SoC clock design and operating configuration.

U3 is a five-position DIP switch used to set the core selection signals. Each signal has a pull-down resistor: when the switch is open the signal is low, and when the switch is closed it is connected to 3.3 V through a resistor and becomes high. The five signals form a selection code; which processor core a given code corresponds to must be looked up in the core selection table for that chip.

| DIP switch pin pair | Corresponding signal | Main controller package pin |
| :------------------ | :------------------- | :-------------------------- |
| 1—10                | `CORE_SEL_4`         | 106                         |
| 2—9                 | `CORE_SEL_3`         | 107                         |
| 3—8                 | `CORE_SEL_2`         | 108                         |
| 4—7                 | `CORE_SEL_1`         | 109                         |
| 5—6                 | `CORE_SEL_0`         | 110                         |

#### Power Supply and Reset

The 5 V input from Type-C first passes through the power switch SW9 and then through the resettable fuse U9 to form the on-board `VCC_5V` supply. Two RT2515HGSP regulators further generate 3.3 V and 1.2 V:

| Power     | Generation method                    | Main uses                                            |
| :-------- | :----------------------------------- | :--------------------------------------------------- |
| **5 V**   | Type-C input, via switch and fuse    | Seven-segment display driver, power chip input, and expansion header supply |
| **3.3 V** | U7 regulator output                  | Main controller IO, memory, sensors, downloader, etc. |
| **1.2 V** | U8 regulator output                  | Main controller core supply                          |

U4 is a TPS3808G01DBVR reset supervisory chip, responsible for monitoring the power supply and generating the reset signal. The main controller reset button SW10 is connected to its manual reset input, and the reset output is connected to the main controller `RST_N_I` through R26. This connection combines button reset with power monitoring. **The GPIOs on the expansion interface use 3.3 V logic levels.** The presence of a 5 V power pin on the header does not mean that the GPIOs can accept 5 V signals.


### Memory System

| Type          | Reference designator and part number | Capacity           | Retained after power loss | Main uses              |
| :------------ | :----------------------------------- | :----------------- | :------------------------ | :--------------------- |
| **SPI Flash** | U5, W25Q128JVSIQ                     | 128 Mbit (16 MB)   | Retained                  | Storing firmware and persistent data |
| **PSRAM**     | U11, marked in the project as 3.3 V, 64 Mbit | 64 Mbit (8 MB) | Not retained          | Storing runtime data and buffers |
| **EEPROM**    | U26, AT24C64D-SSHM-T                 | 64 Kbit (8 KB)     | Retained                  | Storing configuration parameters, calibration values, etc. |

A bit is a binary digit and a Byte is a byte; 8 bits equal 1 Byte, so 128 Mbit corresponds to 16 MB. The project does not give the full part number of U11, nor does it give the on-chip RAM capacity of the main controller or the memory address mapping; these parameters need to be confirmed with the accompanying chip documentation.

### Peripheral Modules
#### Communication and Expansion

* **UART**: Dedicated system serial port, connected to the on-board CP2102, used for communication between the computer and the main controller.
* **UART1**: Multiplexed via GPIO to H1, usable for communication with the ESP-01S module.
* **I2C**: Connects the temperature and humidity sensor and the EEPROM, and is routed to the U10 expansion header.
* **SPI / QSPI**: Some GPIOs can be multiplexed as serial communication signals; H3 uses the clock, chip select, and main-controller transmit data lines to connect the SPI screen.
* **GPIO**: Can be used for button reading, LED control, and connecting external modules; the on-board sharing relationships need to be taken into account when using them.

#### Display, Acquisition, and Control

* **Four-digit seven-segment display**: Two dual-digit seven-segment displays form a four-digit display, driven uniformly by the TM1650.
* **AHT20**: Digital temperature and humidity sensor, returning temperature and relative humidity data over I2C.
* **User buttons and LEDs**: Two of each, usable for basic input and output experiments.
* **Buzzer**: Driven through a transistor by the PWM function corresponding to GPIO1_14. PWM is pulse-width modulation, which can output periodic pulses.
* **Screen interface**: H3 provides the power and control signals needed to connect an SPI TFT screen; the screen itself must be connected externally.


## Board Introduction

![StarrySky-L4 board feature overview](../../../res/img/brd/starry-sky-l/v4.0/board.webp)

The figure uses the board render corresponding to the V0.3_C2_3 project, and the labels are intended to help first-time users locate the functional areas on the board.

* **System**: 1 Type-C interface, 1 power switch, 1 power indicator LED, and 3.3 V and 1.2 V power circuits.
* **Main controller and storage**: 1 main controller, 2 active crystal oscillators, 1 core selection DIP switch, and 1 each of Flash, PSRAM, and EEPROM.
* **Communication and download**: 1 USB-to-serial channel, 1 HFP-LINK downloader, and 1 LINK mode switch.
* **On-board peripherals**: 4-digit seven-segment display, 2 user buttons, 2 user LEDs, 1 buzzer, and 1 temperature and humidity sensor.
* **Expansion interfaces**: 1 set of 40-pin IO header, 1 set of 8-pin SPI TFT interface, and 1 set of 8-pin ESP-01S interface.

### Type-C, UART, and HFP-LINK

Type-C is the main interface connecting the board to the computer, providing 5 V power and a USB data path. Its data lines first enter **U13 (TS3USB221ARSER)**, and then, depending on the state of the LINK switch, are connected to either the CP2102 or the HFP-LINK.

The CP2102 is a USB-to-serial chip, responsible for converting data between the computer's USB communication and the main controller's UART. The main controller's `UART_TX` is the transmit signal, connected to the RXD of the CP2102; the main controller's `UART_RX` is the receive signal, connected to the TXD of the CP2102. TX means transmit and RX means receive, so the two devices are connected transmit-to-receive.

The HFP-LINK uses a separate **U17 (CH32V103C8T6)**. It receives data from the computer over USB and accesses the on-board Flash via SPI. The Flash's four communication lines pass through **U14 (SN74CB3Q3257PWR)**, which selects the access path between the main controller and the downloader.

**SW17 does more than switch the USB connection; it also determines who accesses the Flash.** U13 and U14 share the `FLASH_SEL` control signal. The two states are as follows:

| `FLASH_SEL` level | Type-C data path | Flash connected to | Corresponding use                              |
| :---------------- | :--------------- | :----------------- | :--------------------------------------------- |
| **Low**           | CP2102           | U2 main controller | The main controller accesses the firmware and communicates with the computer over the serial port |
| **High**          | HFP-LINK         | U17 downloader     | The downloader accesses the Flash              |

The board also has a downloader reset button **SW1** and an indicator LED **LED4**. SW1 resets the HFP-LINK, whereas main controller reset uses SW10; do not confuse the two.



### Buttons and Indicator LEDs

| Function                  | Component reference designator | Connection                        | State description                                      |
| :------------------------ | :----------------------------- | :-------------------------------- | :----------------------------------------------------- |
| **Power indicator LED**   | LED1                           | 3.3 V power supply                | Indicates the state of the 3.3 V supply, not controlled by a main controller GPIO |
| **User LED 0**            | LED2                           | GPIO1_5, main controller pin 54   | Lit when the output is low, off when the output is high |
| **User LED 1**            | LED3                           | GPIO1_6, main controller pin 55   | Lit when the output is low, off when the output is high |
| **User button 0**         | SW5, KEY-1                     | `BUTTON0` / GPIO1_7, main controller pin 56 | High when released, low when pressed |
| **User button 1**         | SW22, KEY-2                    | `BUTTON1` / GPIO1_8, main controller pin 57 | High when released, low when pressed |
| **Main controller reset button** | SW10, RST                | Controls `RST_N_I` via U4         | Pressing it triggers a main controller reset           |
| **Downloader reset button** | SW1                          | `HFP_NRST`                        | Pressing it resets the HFP-LINK                        |
| **Downloader indicator LED** | LED4                        | PA1 of U17, connected via a resistor | Controlled by the downloader firmware, cannot be used as a user LED |

One end of a user LED is connected to 3.3 V through a resistor, and the other end is connected to a GPIO. When the GPIO outputs low, current can flow through the LED, so it is "lit when low". The user buttons, on the other hand, are held high by pull-up resistors, and pressing them grounds the corresponding signal. Here, **LED2 and LED3 are component reference designators, while LED0 and LED1 are user control signal names**. The schematic also contains a power indicator LED with the reference designator LED1, so when looking things up you should check both the reference designator and the functional area it belongs to.


### On-Board Storage
#### SPI Flash: Storing Firmware

U5 is a **W25Q128JVSIQ** with a capacity of **16 MB**. It is suitable for storing firmware and other data that needs to be retained for a long time; its contents are not lost when power is removed.

This board uses a standard SPI connection, with separate data lines for transmit and receive. The communication signals on the Flash chip side are as follows:

| Function              | Flash pin name | On-board signal | Purpose                                        |
| :-------------------- | :------------- | :-------------- | :--------------------------------------------- |
| **Chip select**       | CS#            | `FLASH_CS0`     | Pulling it low selects the Flash; pulling it high ends the current transaction |
| **Clock**             | CLK            | `FLASH_CLK`     | Provides the synchronization rhythm for data transmission and reception |
| **Flash data input**  | DI             | `FLASH_MOSI`    | Receives commands, addresses, and write data sent by the main controller or downloader |
| **Flash data output** | DO             | `FLASH_MISO`    | Returns data and chip status to the main controller or downloader |

**CS is chip select (Chip Select), and # indicates active low.** DI and DO mean input and output respectively, with the direction referenced to the Flash. MOSI denotes data that the current host sends to the Flash, and MISO denotes data that the Flash returns to the current host; the host here is selected by the LINK switch and can be either U2 or the HFP-LINK.

The Flash's other two pins, IO2 and IO3, are pulled up to 3.3 V through resistors; this board does not connect them to the main controller as a four-line data path. Therefore, you should distinguish between "the communication modes supported by the chip itself" and "the connection method actually used on this board".

#### PSRAM: Storing Runtime Data

U11 is the on-board **PSRAM**, described in the project component data as **3.3 V, 64 Mbit, i.e., 8 MB**. It can be used to store variables, caches, and other program runtime data, and its contents are lost when power is removed. The project does not fill in the complete part number; the specific device model is subject to the physical board and the final bill of materials.

PSRAM can be understood as a kind of expansion memory intended for runtime data. This board connects four data lines to it, used to transfer data between the main controller and the memory:

| PSRAM signal      | Main controller GPIO | Purpose                     |
| :---------------- | :------------------- | :-------------------------- |
| **CE / chip select** | GPIO0_0           | Selects the PSRAM to communicate with |
| **CLK / clock**   | GPIO0_7              | Synchronizes data transfer  |
| **IO0**           | GPIO0_2              | Data line 0                 |
| **IO1**           | GPIO0_3              | Data line 1                 |
| **IO2**           | GPIO0_4              | Data line 2                 |
| **IO3**           | GPIO0_5              | Data line 3                 |

The four data lines here indicate the interface transfer width, while 8 MB indicates the total storage capacity; the two are not the same concept. The main controller also provides a multiplexed signal corresponding to `PSRAM_CS1`, but only one U11 is fitted on the current board.

#### EEPROM: Storing Configuration Parameters

U26 is an **AT24C64D-SSHM-T** with a capacity of **8 KB**. EEPROM is an electrically erasable non-volatile memory, suitable for storing small amounts of data such as device settings and calibration parameters, and it retains them when power is removed.

It connects to the main controller via I2C: `GPIO0_27` is SCL (clock) and `GPIO0_28` is SDA (data). The three address configuration pins A0, A1, and A2 are all grounded, giving a **7-bit I2C address of `0x50`**. WP is the write-protect pin; it is currently grounded, allowing writes. For capacity and address rules, refer to the [official AT24C64D documentation](https://www.microchip.com/en-us/product/AT24C64D).

The I2C address is used to select a device on the bus; it is not the storage address of a particular byte in the EEPROM, nor is it the processor's memory base address.

### Four-Digit Seven-Segment Display

The board uses two **GS2020CR-G dual-digit seven-segment displays**, with reference designators LED10 and LED11, combined into a four-digit display. Each digit consists of several light-emitting segments; by controlling which segments light up, the driver chip can display digits and some characters.

The display is driven by **U1 (TM1650)**. The main controller sends display data to it over two signal lines:

| Function | On-board signal | Main controller connection |
| :------- | :-------------- | :------------------------- |
| **Clock** | `SEG_CLK`      | GPIO1_10, pin 59           |
| **Data**  | `SEG_DAT`      | GPIO1_9, pin 58            |

The TM1650 then controls the selection of the individual segments and digits, so the main controller does not need to connect every light-emitting segment of the four digits one by one. U1 is powered from 5 V, and the two main controller communication lines are pulled up to 3.3 V through resistors. This two-wire interface is connected separately from the I2C lines used by the AHT20 and the EEPROM.

### Temperature and Humidity Sensor

U15 is an **AHT20**, used to measure ambient temperature and relative humidity and to output digital results over I2C. It shares GPIO0_27 and GPIO0_28 with the EEPROM, and 4.7 kΩ pull-up resistors are provided on the board.

The AHT20's **7-bit I2C address is `0x38`**, which differs from the EEPROM's `0x50`, so they can share the same SCL and SDA signals.

### Buzzer

BUZZER1 is an **MLT-5020**, driven by transistor **Q2 (S8050)**. The `PWM0_D0` signal from main controller GPIO1_14 is connected to Q2 through a resistor, and Q2 in turn controls the current path of the buzzer. In this arrangement the transistor handles the load drive, and the main controller only outputs the control signal. The 4 kHz marked on the schematic is a parameter of the buzzer-related components; the actual sound also depends on the drive waveform and cannot be taken as the program's default output frequency.



## Interface Signals
### IO Expansion Header U10

U10 is a **2 × 20, 2.54 mm pitch, 40-pin header**, providing 29 GPIOs as well as 5 V, 3.3 V, and GND. GND denotes the common ground; when connecting external modules, a common ground is required.

The table below lists the mapping according to the project pin numbering. It is a pin numbering table; before wiring, confirm the orientation against the pin 1 marking on the PCB.

| Odd pin | Signal   | Even pin | Signal   |
| :------ | :------- | :------- | :------- |
| 1       | 5 V      | 2        | GND      |
| 3       | 5 V      | 4        | GND      |
| 5       | 5 V      | 6        | GND      |
| 7       | 3.3 V    | 8        | GND      |
| 9       | 3.3 V    | 10       | GND      |
| 11      | 3.3 V    | 12       | GPIO0_28 |
| 13      | GPIO0_27 | 14       | GPIO0_26 |
| 15      | GPIO0_25 | 16       | GPIO0_24 |
| 17      | GPIO0_23 | 18       | GPIO0_22 |
| 19      | GPIO0_12 | 20       | GPIO0_13 |
| 21      | GPIO0_14 | 22       | GPIO0_15 |
| 23      | GPIO0_16 | 24       | GPIO0_17 |
| 25      | GPIO0_18 | 26       | GPIO0_19 |
| 27      | GPIO0_20 | 28       | GPIO0_21 |
| 29      | GPIO1_14 | 30       | GPIO1_15 |
| 31      | GPIO1_16 | 32       | GPIO1_17 |
| 33      | GPIO1_18 | 34       | GPIO1_19 |
| 35      | GPIO1_20 | 36       | GPIO1_21 |
| 37      | GPIO2_8  | 38       | GPIO2_9  |
| 39      | GPIO2_10 | 40       | GPIO2_11 |

**Some signals on the expansion header are also connected to on-board devices.** They are not additional, independent GPIOs:

| U10 pin         | Shared signal                | Function already connected                 |
| :-------------- | :--------------------------- | :----------------------------------------- |
| **12, 13**      | GPIO0_28, GPIO0_27           | I2C data line and clock line of the AHT20 and EEPROM |
| **14, 15**      | GPIO0_26, GPIO0_25           | UART1 receive and transmit lines of H1     |
| **16, 19, 23**  | GPIO0_24, GPIO0_12, GPIO0_16 | Screen clock, transmit data, and chip select of H3 |
| **29**          | GPIO1_14                     | Buzzer control path                        |

For example, when GPIO1_14 is used as an expansion output, the on-board buzzer driver also receives the same signal; when using the screen interface, you must not let another peripheral actively drive the same signal lines at the same time.

### SPI TFT Screen Interface H3

H3 is a 1 × 8 socket, with the on-board silkscreen label `SPI_TFT`. It provides screen power, SPI communication, and display control signals, and is suitable for connecting SPI TFT modules whose pin definitions match.

| H3 pin | Function              | On-board signal / main controller GPIO | Purpose                          |
| :----- | :-------------------- | :------------------------------------- | :------------------------------- |
| 1      | Ground                | GND                                    | Common ground                    |
| 2      | Power                 | 3.3 V                                  | Powers a matching screen module  |
| 3      | SPI clock             | `SPI_CLK` / GPIO0_24                   | Synchronizes screen communication |
| 4      | SPI transmit data     | `SPI_MOSI` / GPIO0_12                  | Main controller sends data to the screen |
| 5      | Screen reset          | `LCD_RES` / GPIO0_30                   | Controls screen reset             |
| 6      | Data / command select | `LCD_DC` / GPIO0_29                    | Distinguishes display data from control commands |
| 7      | Screen chip select    | `SPI_CS0` / GPIO0_16                   | Selects the screen for communication |
| 8      | Backlight control     | `LCD_BLK` / GPIO0_31                   | Breaks out the screen backlight control signal |

This interface does not break out a MISO receive line; the current connection is mainly used for the main controller to send data to the screen. Power supplies, backlight drives, and pin arrangements may differ between screen modules, so this table should be checked item by item when selecting one.

### ESP-01S Module Interface H1

H1 is a 2 × 4 socket, with the on-board silkscreen label `ESP-01S`, used to install the corresponding wireless module. It connects to main controller UART1 and provides a 3.3 V power supply; the interface itself does not include the wireless module.

| H1 pin | On-board connection   | Description                    |
| :----- | :-------------------- | :----------------------------- |
| 1      | `UART1_RX` / GPIO0_26 | Line on which the main controller receives data |
| 2      | GND                   | Common ground                  |
| 3      | Pulled up to 3.3 V via R67 | Pull-up connection for a module control pin |
| 4      | Not connected         | No signal connected in the schematic |
| 5      | Pulled up to 3.3 V via R68 | Pull-up connection for a module control pin |
| 6      | Not connected         | No signal connected in the schematic |
| 7      | 3.3 V                 | Module power supply            |
| 8      | `UART1_TX` / GPIO0_25 | Line on which the main controller transmits data |

The transmit and receive directions in this table are referenced to the main controller. The pin numbering of H1 is according to the project; before installing a module, check the module pins and insertion orientation, and do not judge by the socket shape alone.
