## Introduction
The StarrySky-L uses a mounting design consisting of an SoC main board plus an FPGA system-on-module (SoM), and accesses memory through the ChipLink protocol.

![](../../../res/img/brd/starry-sky-l/v3.0/brd_func_top.webp)

![](../../../res/img/brd/starry-sky-l/v3.0/brd_func_bot.webp)

The peripherals and interfaces of the StarrySky-L are described in detail below:

- System
    - 1 power switch, red power indicator LED
    - 1 JTAG debug and flashing interface for the FPGA
    - 1 Type-C power interface (also serves as the SoC's UART interface)
    - 1 2-position DIP switch for the FPGA boot mode
    - 1 drag-and-drop on-board programmer — HFP-Link
- SoC
    - 1 25 MHz active crystal oscillator, 1 12.288 MHz active crystal oscillator
    - 1 FLASH socket with a built-in NOR FLASH chip; after reset, the SoC fetches instructions from this FLASH chip
    - 1 UART interface, using a CP2102 for protocol conversion
    - 1 4-position DIP switch for PLL configuration
    - 1 5-position DIP switch for core selection
    - 1 reset button
    - 1 PS2 interface
    - 1 SPI screen interface
    - 2 independent buttons
    - 4 independent LEDs
    - 2 on-board I2C devices (PCF8563BM/TR, AT24C64D-SSHM-T)
    - 1 SD card slot
    - 1 40-pin IO interface

The StarrySky-L does not provide a pin breakout for the FPGA IO, so the FPGA is not covered in detail here. Interested students can download the corresponding resources from the repository, or refer to the documentation for [StarrySky v2.1](v2.1.md).

## Power-On Test
In this chapter, students need to complete the confirmation of the following items. More detailed operating instructions are provided later:

- Whether the PCB board powers on normally
- Whether the FPGA board is working normally
- Whether the default test program works normally

### Detailed Instructions
#### Checking the Board Power Status
!!! danger "Danger"
    Do not place the board on any conductor! After power-on, do not touch the exposed solder joints and pads of the board with your hands!!!

Before powering on the board, set the power switch to the off position (lever away from the Type-C connector). After confirming the switch state and the placement of the board, connect the board to the computer using the Type-C data cable, close the power switch (lever toward the Type-C connector), and observe whether the red LED near the Type-C connector lights up.

![](../../../res/img/brd/starry-sky-l/v3.0/brd_pwr.webp)

#### Checking the FPGA Working Status
After the board is powered on, observe the FPGA working indicator LEDs at the bottom of the board: one red power indicator LED and one blue configuration indicator LED. When the FPGA is working normally, both LEDs remain lit. If the blue LED does not light up, use the DIP switch to configure the FPGA into FLASH mode.

## Program Compilation and Flashing
This section introduces the program compilation and flashing process, so that the board can run other corresponding applications rather than just the test case. The flashing process has already been described in detail in the StarrySky v2.1 documentation, so only the differences are covered here.

### Compiling Programs
For this StarrySky-L, half of the compilation environment is provided (the AM part still needs to be completed by you), and the corresponding reference code can be downloaded from the [StarrySkyPi](https://github.com/OSESO/StarrySkyPi) repository.

First, add the two files `ysyx.h ysyx.c` to klib. This header file encapsulates the peripheral driver functions, and through the APIs it provides you can quickly call the peripherals to achieve the effects you want. You are welcome to submit PRs to help build and improve this header file.

After the header file has been added, you can use the `run.py` script to compile under the `you_path/ysyx_env/prog/src` path. This script requires two optional parameters, `APP_NAME` and `APP_TYPE`. For specific usage, `RTFSC` on your own. Example:

![](../../../res/img/brd/starry-sky-l/v3.0/soft_riscv_build.webp)

After the program is compiled, the corresponding binary file will be generated under the `you_path/ysyx_env/prog/bin/mem` path.

!!! quote "Compiling the program into SRAM"
    The mem of the StarrySky-L is still the same as that of StarrySky v2.1: it accesses the memory chips on the FPGA through ChipLink, and switching between multiple buses makes memory access a performance bottleneck. This SoC integrates 64K of on-chip SRAM, so relatively small programs can be compiled to run on the SRAM; at the same time, the stack location and size must be managed properly. In this way, our chip can leave the FPGA behind and run programs on its own, making the development of small embedded systems possible.

## Hardware Design
### Overview
- LCEDA (JLC EDA) was used for schematic and PCB design, and JLC was used for PCB production and SMT manufacturing
    - A four-layer stack-up design was adopted, with the stack-up structure using the JLC JLC04161H-3313 stack-up design for impedance control
    - The board's mechanical dimensions are 90 mm * 63 mm, with a board thickness of 1.6 mm
    - Matte black solder mask, 1 µ" (micro-inch) immersion gold, outer copper thickness 1 oz, inner copper thickness 0.5 oz
- Length matching control
    - CHIPLINK 20 mil
    - JTAG 20 mil
    - USB 20 mil
- Clock crystal oscillator ground shielding

### Schematic Design
The power of the StarrySky-L is brought in from the Type-C port and, after passing through a slide switch and a resettable fuse, feeds three independent LDO circuits that step it down to 3.3 V, 1.8 V, and 0.9 V respectively. When the power module is working normally, a red LED lights up.

![](../../../res/img/brd/starry-sky-l/v3.0/brd_sch_pwr.svg)
/// caption
Power module
///

The chip peripheral circuits include the clock circuit, core selection circuit, PLL configuration circuit, and reset circuit.

- The clock circuit uses two active crystal oscillators: 25 MHz provides the clock for the core, and 12.288 MHz provides the clock for peripherals
- The core selection and PLL circuits are designed with positive logic DIP switches
- The reset circuit uses a dedicated reset chip, which can generate a relatively clean reset signal for the chip and prevent interference in the circuit from affecting the reset signal

![](../../../res/img/brd/starry-sky-l/v3.0/brd_sch_chip.svg)
/// caption
Chip peripherals
///

The difference between the FPGA peripheral circuit and that of StarrySky v2.1 is that the **BOOT MODE** DIP switch has also been changed to positive logic operation.

![](../../../res/img/brd/starry-sky-l/v3.0/brd_sch_fpga.svg)
/// caption
FPGA peripherals
///

External interfaces:

- Four BTB connectors for connection to the FPGA
- Type-C interface for power supply and serial connection
- GPIO function pin breakout

![](../../../res/img/brd/starry-sky-l/v3.0/brd_sch_io.svg)
/// caption
External interfaces
///

Storage module:

- Drag-and-drop downloader based on the CH32V103C8T6 — HFP_LINK
- SD card connector

![](../../../res/img/brd/starry-sky-l/v3.0/brd_sch_mem.svg)
/// caption
Storage module
///

On-board peripherals:

- The PS2 interface performs level conversion between 5 V and 1.8 V
- The I2C section, after 1.8 V to 3.3 V conversion, connects to the PCF8563 RTC clock and the AT24C64D memory
- Independent buttons are pulled up with 4.7K resistors
- The IOs connected to the LEDs are pulled up by default, and the LEDs are connected in series with 4.7K resistors for current limiting
- SPI screen interface (2.54 mm socket) * 1
