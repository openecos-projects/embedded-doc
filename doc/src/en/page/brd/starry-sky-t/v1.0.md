# Getting Started
## Project Overview

The StarrySky-T1 is a development board for RISC-V SoC learning and embedded prototype validation. The board is centered on the U1 main control chip and is equipped with external SDRAM, SPI Flash, I2C EEPROM, USB, Ethernet, UART, JTAG, and general-purpose IO interfaces. The accompanying software is [ECOS-SDK](https://github.com/openecos-projects/embedded-sdk), currently using the `board/StartySkyT1` board support package in the `2.1-dev` branch.


## Chip Introduction

### Hardware Architecture

| Item           | Description                          |
| :------------- | :----------------------------------- |
| **Processor Core** | 32-bit RISC-V processor          |
| **Instruction Set Architecture** | RISC-V `rv32imc_zicsr_zifencei` |
| **Operating Frequency** | 20 MHz                      |
| **Target Architecture** | `riscv-none-elf`, `ilp32` ABI |
| **External Clock** | OSC1, 20 MHz                    |

### Memory System

| Type              | Capacity       | Address Range               | Description                                                |
| :---------------- | :------------- | :-------------------------- | :--------------------------------------------------------- |
| **On-chip DSRAM** | 16 KB          | `0x01800000` - `0x01803FFF` | Data, BSS, heap, and stack region in the SDK default linker script |
| **On-chip ISRAM** | 16 KB test region | Starting at `0x01000000` | Test region defined by SDK headers; the current default linker script does not place applications here |
| **SPI Flash XIP** | 16 MB          | `0x20000000` - `0x20FFFFFF` | Program code and read-only data execute here by default |
| **External SDRAM** | 32 MB         | `0x80000000` - `0x81FFFFFF` | 16-bit data bus; the SDRAM controller must be initialized first |

### Peripheral Modules

The current SDK's StartySkyT1 board support package includes the following drivers:

#### Communication Interfaces

* **SYS_UART**: System UART, default baud rate 115200
* **I2C0**: I2C host polling driver
* **QSPI0**: QSPI host driver, can connect to the onboard W25Q128 Flash

#### Storage and Control

* **GPIO**: 4 GPIO groups with 8 pins each, for a total of 32 GPIOs
* **SDRAM**: Initialization driver for the 32 MB external SDRAM
* **Timer0**: Timer polling and periodic interrupt driver
* **CLINT**: Driver for accessing the `mtime` and `mtimecmp` timers
* **PLIC**: Machine-mode external interrupt distribution, supporting GPIO and Timer0 interrupts

#### Onboard Hardware

* **USB**: Onboard CH374T USB controller
* **Ethernet**: Onboard CH395F Ethernet controller
* **I2C EEPROM**: Onboard AT24C64D device connected to the I2C bus
* **HFP-LINK**: Onboard programmer controlled by a separate CH32V103C8T6

## Board Features

Board diagram to be added.

### Power

* The board has multiple USB Type-C connectors, and the power nets include USB_5V and USB1_VCC; when connecting, distinguish their purposes by the silkscreen next to each connector.
* U4 and U5 are RT2515HGSP power chips that generate the 3V3 and 1V2 rails, respectively.
* The board provides power indicator LED1.
* SW2 is the power switch.
* The main control chip uses a 3.3 V IO supply and a 1.2 V core supply; before power-up, do not input voltages above 3.3 V directly to the IO pin headers.

### Communication and Expansion

* **UART**: The CP2102-GMR converts the main controller UART into a USB virtual serial port, with the UART_TX/UART_RX signals; the corresponding connector is used for serial debugging.
* **USB**: The onboard USB Type-C connector connects to the CH374T USB controller.
* **Download link**: The connector marked `LINK` connects to HFP-LINK; the connector marked `USB` is used for the USB controller or other USB functions.
* **Ethernet**: The CH395F Ethernet controller connects to the HR911105A network transformer and RJ45 connector, with the ETH_LED0 and ETH_LED1 indicator signals.
* **JTAG**: The IO page provides 4-wire JTAG signals, and there is also an independent IOJTAG pin header.
* **IO pin header**: U7 is a PZ2.54-2*20 dual-row pin header, providing two groups of 20-pin 3.3 V IO expansion.

### Buttons and Indicator LEDs

* **RST**: Main controller reset button; pressing it asserts RST_N.
* **BUTTON0, BUTTON1**: Connected to main controller general-purpose inputs, usable for user interaction tests.
* **LED0, LED1**: Connected to main controller general-purpose outputs, usable for indicating program running status.
* **BOOT_SEL**: Boot address selection signal, used to select the main controller boot mode; the actual active level and boot address are subject to the SoC design and SDK documentation.
* **FLASH_SEL**: Flash path selection signal, used to switch between HFP-LINK and the main controller Flash interface.

## Interface Signals

### IO Pin Header

U7 is a 2x20 pin header with a 2.54 mm pitch. The main signals brought out in the schematic include:

* `gpioa2`, `gpioa3`, `gpioa4`, `gpioa5`, `gpioa6`, `gpioa7`
* `gpioc6`, `gpioc7`
* `gpiod0` through `gpiod7`
* `I2C_SCL`, `I2C_SDA`
* `QSPI_CLK`, `QSPI_CS0`, `QSPI_DATA0` through `QSPI_DATA3`
* `DBG_TCK`, `DBG_TDI`, `DBG_TDO`, `DBG_TMS`
* `3V3` and `GND`


### JTAG Pin Header

The IOJTAG interface on the IO page brings out:

| Signal    | Description    |
| :-------- | :------------- |
| `DBG_TCK` | JTAG clock     |
| `DBG_TDI` | JTAG data input |
| `DBG_TDO` | JTAG data output |
| `DBG_TMS` | JTAG mode select |
| `3V3`     | Target board power reference |
| `GND`     | Ground         |

## Power-Up and Basic Testing

1. Confirm that the board has no short circuits and that the power switch is off.
2. Use a USB Type-C data cable to connect the board to the PC. Prefer the connector labeled power, serial, or `LINK`, and make sure the cable can supply power.
3. Turn on SW2 and check whether the red power indicator LED1 lights up.
4. Press and release the RST button, and check whether the serial terminal shows boot output.
5. To test UART, select the serial port corresponding to the CP2102 on the PC and configure the serial parameters according to the current SDK example; the common configuration is 115200, 8 data bits, no parity, and 1 stop bit.
6. To test external memory, run read/write tests for SDRAM, SPI Flash, and I2C EEPROM separately; do not rely solely on serial output to determine that the memory is working.

## Development Workflow

### Development Environment Configuration

1. Install ECOS-SDK and its dependencies, and complete the environment variable configuration.

2. Create your own project directory outside the SDK; do not directly modify the template files under the SDK installation directory.

3. Use `ecos init_project` to create a project and specify the target board as `t1`. `t1` is the board alias used by the SDK command line, and `StartySkyT1` is the BSP directory name in the repository. For example:

   ```bash
   ecos init_project hello -name t1_hello -target t1
   cd t1_hello
   ```

4. Run `make menuconfig` to configure the project. The T1 board's default configuration uses a 20 MHz CPU, 115200 baud, and 16 KB DSRAM; drivers such as GPIO, Timer, CLINT, SDRAM, I2C, and QSPI are disabled by default and must be enabled manually when needed.

   The SDK provides templates for T1 such as `hello`, `gpio`, `gpio_interrupt`, `timer`, `timer_interrupt`, `clint`, `plic`, `sdram`, `i2c_scan`, `i2c_eeprom`, `qspi_psram`, `isram`, `asm_hello`, and `asm_gpio`, which can be created directly with `ecos init_project <template-name> -target t1`.

5. Build the project:

   ```bash
   make
   ```

   Normally, the firmware files are located in the `build/` directory, including the ELF debug file, BIN binary file, and disassembly text. A normal C project uses `sections.lds`; program code is linked by default to the Flash XIP address `0x20000000`, and data and stack use the 16 KB DSRAM.

### HAL Interfaces

The T1 board drivers are implemented according to the ECOS-SDK HAL interfaces. When developing applications, the following API families are recommended:

* `hal_sys_uart_*`: System UART initialization, transmit, and receive
* `gpio_hal_*`: GPIO direction, input/output, and alternate function configuration
* `hal_i2c_*`: I2C0 host read/write
* `hal_qspi_*`: QSPI0 read/write and command operations
* `hal_timer_*`, `hal_delay_ms()`: Timer0 and delays
* `hal_clint_*`, `hal_sys_tick_*`: CLINT timing and system tick
* `hal_intr_*`: PLIC interrupt initialization, request, enable, and release

Direct register access is suitable for low-level debugging and is not recommended as the default approach for ordinary applications. In particular, GPIO alternate function and input/output configuration should be done through the HAL interfaces.

### Recommended Basic Tests

The following order is recommended for board validation:

1. **UART test**: Enable SYS_UART, connect to the serial port corresponding to the CP2102, and run a UART output example.
2. **GPIO test**: Enable GPIO and use the onboard LED0 and LED1 or BUTTON0 and BUTTON1 for input/output tests; for specific GPIO multiplexing, refer to the schematic net names and SDK examples.
3. **Timer/CLINT test**: Test Timer0 polling delays first, then test Timer0 interrupts and the system tick.
4. **SDRAM test**: Enable the SDRAM driver, call the initialization function first, and then perform read/write tests on the 32 MB region starting at `0x80000000`.
5. **Flash/QSPI test**: Enable the QSPI driver and test device identification, read/write, and erase operations on the onboard W25Q128.
6. **I2C test**: Enable I2C0 and connect the onboard AT24C64D or an external I2C device for read/write tests.

### Firmware Download and Boot

The board uses the onboard HFP-LINK to assist with firmware download. HFP-LINK is implemented by U14 (CH32V103C8T6) and communicates with the PC over USB; its SPI signals connect to the main controller Flash interface through the Flash path selection circuit.

When using the `ecos-flash` script provided by the SDK, the following sequence is recommended:

1. Build to generate `build/retrosoc_fw.bin` or a `.bin` file with the name corresponding to the project configuration.

2. Connect the onboard HFP-LINK connector to the PC with a USB data cable.

3. Set `BOOT_SEL` and `FLASH_SEL` according to the board silkscreen so that the Flash path is connected to HFP-LINK.

4. In the project directory, run:

   ```bash
   ecos-flash
   ```

   By default, the SDK script looks for the `/run/media/$USER/YSYX-HFPLnk` mount directory and copies the BIN file to the programmer.

5. After the download completes, disconnect HFP-LINK, switch `FLASH_SEL` to the main controller side, and set the normal boot state.

6. Power-cycle the board or press RST, then open the UART serial terminal to confirm that the program starts.

The toggle direction and active levels of `BOOT_SEL` and `FLASH_SEL` must follow the board silkscreen, the programmer tool version, and the SoC boot design; for first-time operation, power off before changing switch states.
