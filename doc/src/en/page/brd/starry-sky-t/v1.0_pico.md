# Board Introduction

StarrySkyT1 Pico is a development board for RISC-V SoC learning and embedded prototyping. **The board features 32 MB SDRAM, 16 MB SPI Flash, a USB-to-UART circuit, and GPIO, I2C, QSPI, and JTAG expansion interfaces**, and can be used for experiments such as serial communication, button control, memory read/write, and peripheral expansion.

The board is powered through a Type-C connector and uses a CP2102 to convert the main controller UART into a serial port recognized by a computer. Onboard LEDs and buttons provide basic input/output functions. Two IO pin headers are used to connect external modules, and the JTAG/Flash pin header brings out the signals required for debugging and memory access.


## Chip Introduction
### Hardware Architecture

The board is centered on the U1 main controller and consists of the processor, memory interfaces, communication interfaces, and associated clock, power, and reset circuits. **The main controller connects to non-volatile storage through a dedicated Flash interface, to runtime memory through an SDRAM interface, and exchanges data with external devices through UART, I2C, QSPI, and GPIO.**

| Item | Description |
| :--- | :--- |
| **Main control chip** | U1, engineering device name `202601_ECOS_SOC6`, responsible for program execution, memory access, and peripheral control |
| **Processor architecture** | RISC-V; peripherals are connected through the corresponding main controller interfaces |
| **External clock** | OSC1, model OT2EL89CJI-111YLC-20M, 20 MHz active crystal oscillator, connected to the clock input on pin 126 of the main controller |
| **Storage interfaces** | One onboard SPI Flash interface and one 16-bit SDRAM interface |
| **Communication interfaces** | UART, I2C, and QSPI; UART connects to the onboard USB-to-serial circuit |
| **GPIO organization** | Four groups: GPIOA, GPIOB, GPIOC, and GPIOD, with eight channels each and 32 in total |
| **Debug interface** | 4-wire JTAG, with TCK, TMS, TDI, and TDO brought out through H3 |
| **IO voltage** | 3.3 V, powering the main controller IO; the U2 pin header also brings out an independent 5 V power pin |
| **Core voltage** | 1.2 V, supplied separately from the IO power |
| **Reset input** | `RST_N_I`, connected to pin 123 of the main controller, active low |
| **Boot selection** | `BOOT_SEL`, connected to pin 124 of the main controller, with the default level set by an onboard resistor |

#### Main Controller and Memory

* **Flash path**: U1 connects to U10 through `FLASH_CS0`, `FLASH_CLK`, `FLASH_MOSI`, and `FLASH_MISO`. This path is used to access the onboard 16 MB SPI Flash, and the same signals are also brought out to the H3 pin header.
* **SDRAM path**: U1 connects to U6 through 16 data lines, 13 address lines, 2 bank address lines, and clock, chip-select, and read/write control signals. Address signals select storage locations, data lines transfer contents, and DQM signals mask data operations for the corresponding bytes.

The two memory interfaces connect to Flash and SDRAM, respectively. Flash stores content that must be retained after power loss, while SDRAM holds data during operation.

#### Communication and Expansion Connections

* **UART path**: U1's UART connects to U11 (CP2102-GMR), and the CP2102 connects to the D+ and D- lines of USB1, forming a USB-to-serial link.
* **I2C and QSPI paths**: The corresponding main controller signals are brought out to the U2 pin header for connecting external devices. QSPI provides a clock, chip select, and four data lines, and is independent of the `FLASH_*` interface used by the onboard Flash.
* **GPIO path**: The four GPIO groups are distributed across the two expansion headers U2 and U3; `gpiod4` is also connected to the user LED, and `gpioa7` to the user button.
* **JTAG path**: The main controller's `DBG_TCK`, `DBG_TMS`, `DBG_TDI`, and `DBG_TDO` signals are brought out to H3 for connection to external debugging equipment.

#### Clock, Power, and System Control

* **Clock source**: OSC1 provides a 20 MHz external clock, which enters the main controller through `OSC_CLK_20M_I`. This value is the crystal oscillator output frequency; the operating frequencies of the main controller's internal modules are determined by the chip clock design.
* **Power structure**: The 5 V input from USB1 feeds `VCC_5V`; two RT2515HGSP devices, U4 and U5, generate 3.3 V and 1.2 V, respectively. The 3.3 V rail powers circuits including the main controller IO, Flash, and SDRAM, while the 1.2 V rail powers the main controller core. The 1.2 V rail is also filtered through the L2 ferrite bead to form `A1V2`, which connects to the PLL analog supply on pin 136 of the main controller.
* **Reset circuit**: `RST_N_I` is pulled up to 3V3 through R27 and connects to C47 and reset button SW3. When the button is pressed, it pulls the reset signal low; when released, the pull-up resistor restores it to high.
* **Boot configuration**: `BOOT_SEL` is pulled down by default through R30; R29 is a reserved pull-up location marked NC, meaning it is not populated by default.



### Memory System

| Type | Model | Capacity | Connection |
| :--- | :--- | :--- | :--- |
| **SPI Flash** | W25Q128JVSIQ | 128 Mbit (16 MB) | `FLASH_CS0`, `FLASH_CLK`, `FLASH_MOSI`, `FLASH_MISO` |
| **External SDRAM** | MT48LC16M16A2P-6A:G | 256 Mbit (32 MB) | 16-bit data bus, 13 address lines, and 2 bank address lines |

* **SPI Flash**: Retains data after power loss and is used to store firmware and other persistent data.
* **SDRAM**: Holds data while the program is running, and its contents are lost after power-off. Before use, the SDRAM controller must be initialized and the timing and refresh parameters configured.
* **Address mapping**: The locations of Flash, SDRAM, and on-chip RAM in the processor address space are determined by the SoC and the linker script; memory capacity cannot be used directly as its access address.

### Peripheral Modules

#### Communication Interfaces

* **UART**: System UART, converted to a USB virtual serial port by the onboard CP2102, used to output logs and transmit/receive data.
* **I2C**: Provides `I2C_SCL` and `I2C_SDA`, allowing external devices such as sensors and EEPROMs to be connected through the IO pin headers.
* **QSPI**: Provides a clock, chip select, and four data lines, allowing external SPI/QSPI devices to be connected through the IO pin headers.

#### Storage and Control

* **GPIO**: Four groups (GPIOA, GPIOB, GPIOC, and GPIOD) with eight channels each, for a total of 32 general-purpose inputs/outputs.
* **Flash interface**: Connects to the onboard W25Q128.
* **SDRAM interface**: Connects to the onboard 32 MB SDRAM and includes address, data, chip-select, clock, and data mask signals.

#### Debugging and System Control

* **JTAG**: Provides TCK, TMS, TDI, and TDO for connecting a debugger that supports this SoC.
* **Reset**: Active low; pressing the reset button puts the main controller into the reset state.
* **BOOT_SEL**: Boot address selection signal, with the default level configured by onboard resistors.



## Board Introduction

![StarrySkyT1 Pico board feature overview](../../../res/img/brd/starry-sky-t/v1.0/t1 pico/board.webp)

* **System**: One Type-C power/serial connector, one power indicator LED, and 3.3 V and 1.2 V power circuits.
* **Main controller and storage**: One main control chip, one 20 MHz active crystal oscillator, one 32 MB SDRAM, and one 16 MB SPI Flash.
* **User interaction**: One reset button, one user button, and one user LED.
* **Communication and expansion**: One USB-to-UART channel, two 2x14 IO pin headers, and one 2x6 JTAG/Flash pin header.

### UART Debug Interface

The onboard USB-to-UART chip U11 is a CP2102-GMR. The main controller's `UART_TX` (pin 111) connects to the CP2102's RXD (pin 25) through R32, and the main controller's `UART_RX` (pin 112) connects to the CP2102's TXD (pin 26) through R31. The CP2102's USB data lines connect to the Type-C connector, enabling serial communication between the computer and the main controller.

### Buttons and Indicator LEDs

| Function | Reference Designator | Signal | Main Controller Connection | State Description |
| :--- | :--- | :--- | :--- | :--- |
| **Power indicator LED** | LED1 | 3V3 power | No GPIO control | Lit when the 3V3 supply is normal |
| **User LED** | LED2 | `LED0` | `gpiod4`, pin 97 | Lit when the GPIO output is low, off when high |
| **User button** | SW1 | `BUTTON0` | `gpioa7`, pin 72 | High when released, low when pressed |
| **Reset button** | SW3 | `RST_N_I` | Pin 123 | Pulls the reset signal low when pressed; returns high when released |

The user LED connects to 3V3 through R28, so a low GPIO output completes the current path and the LED is active-low. The user button is pulled up to 3V3 through R3 and has C23 connected; pressing it grounds `BUTTON0`. LED2 is the reference designator, while LED0 is the name of the main controller control signal, corresponding to `gpiod4`; pins 97 and 72 in the table are chip package pin numbers. The states above are described based on the schematic connections.

### Onboard Memory

The board provides two types of memory, SPI Flash and SDRAM. **Flash stores content that must be retained after power loss, while SDRAM holds data while the program is running.** Both connect to the main controller, but their purposes and connection methods differ.

#### SPI Flash

The onboard SPI Flash is model **W25Q128JVSIQ**, with reference designator **U10** and capacity **16 MB**. It can store firmware and other data that must be retained long-term; its contents are not lost when power is removed.

The main controller communicates with the Flash through a standard SPI interface, using one data line each for transmit and receive. The main communication signals are as follows:

| Function | Flash Chip Pin Name | Board Signal Name | Purpose |
| :--- | :--- | :--- | :--- |
| **Chip select** | CS# | `FLASH_CS0` | The main controller selects the Flash when it drives this signal low and ends the current transaction when it drives it high |
| **Clock** | CLK | `FLASH_CLK` | Provided by the main controller so both sides transmit and receive data at the same rate |
| **Flash data input** | DI | `FLASH_MOSI` | The main controller sends commands, addresses, or data to be written to the Flash |
| **Flash data output** | DO | `FLASH_MISO` | The Flash returns read data or chip status to the main controller |

**In CS#, CS stands for Chip Select and # indicates "active low"**, meaning the Flash is selected when the signal is low. In the schematic, CLK denotes the clock; DI and DO denote data input and data output, respectively, with directions referenced to the Flash chip. Thus, data sent by the main controller enters the Flash's DI, and data returned by the Flash is output from DO.

#### SDRAM

The onboard SDRAM is model **MT48LC16M16A2P-6A:G**, with reference designator **U6** and capacity **32 MB**. It can hold temporary data such as variables and buffers while the program is running, and its contents are lost after power-off.

The SDRAM connects to the main controller through a parallel interface and uses a **16-bit data bus**, meaning one data transfer can carry 16 bits, or 2 bytes. Here, "16-bit" refers to the data transfer width, not the memory capacity.

The connections between the main controller and the SDRAM fall into the following main categories:

* **Data lines**: 16 lines in total, used to transfer data written to or read from the SDRAM.
* **Address and bank select lines**: 13 address lines and 2 bank select lines, used to specify the memory location to access. A bank is a storage partition inside the SDRAM.
* **Clock and control lines**: Used to synchronize data transfers, select the chip, and schedule operations such as reads and writes.
* **Byte mask lines**: DQM0 and DQM1 correspond to the lower and upper 8 data bits, respectively; each group of 8 bits is one byte. For example, when only one byte needs to be written, the other byte can be masked so that its original contents remain unchanged.

**Note: The onboard Flash uses a separate `FLASH_*` interface; the QSPI on the IO pin headers is for connecting external devices. These are not the same connection.**



## Interface Signals

### IO Pin Headers

U2 and U3 are both HC-PZ254-11.5L-2x14PZ, with a 2.54 mm pitch and 28 pins each.

| Interface | Signal Range | Power Pins | Ground Pins |
| :--- | :--- | :--- | :--- |
| **U2** | `gpioc4-gpioc7`, `gpiod0-gpiod7`, I2C, and QSPI | Pins 1, 2, 27, and 28: VCC_5V | Pins 13, 14, 15, and 16: GND |
| **U3** | `gpioa0-gpioa7`, `gpiob0-gpiob7`, `gpioc0-gpioc3` | Pins 1, 2, 27, and 28: 3V3 | Pins 13, 14, 15, and 16: GND |

* **Shared onboard functions**: U2 pin 7 is `gpiod4/LED0`, and U3 pin 9 is `gpioa7/BUTTON0`, shared with the user LED and button, respectively.
* **I2C**: U2 pin 12 is `I2C_SDA`, and pin 17 is `I2C_SCL`.
* **QSPI**: U2 pin 3 is CLK, and pin 26 is CS0; DATA0, DATA1, DATA2, and DATA3 are on pins 25, 4, 24, and 5, respectively.
* **Signal levels**: GPIO, I2C, and QSPI all use 3.3 V logic. VCC_5V on U2 is a power net and does not mean that its signal pins use 5 V logic levels.

### JTAG and Flash Pin Header

H3 is an A2541WR-2x6P with a 2.54 mm pitch and 12 pins; the odd-numbered pins bring out JTAG signals, and the even-numbered pins bring out Flash signals.

| Odd Pin | Signal | Even Pin | Signal |
| :--- | :--- | :--- | :--- |
| 1 | 3V3 | 2 | FLASH_MOSI |
| 3 | DBG_TDO | 4 | GND |
| 5 | DBG_TDI | 6 | FLASH_CLK |
| 7 | DBG_TMS | 8 | FLASH_MISO |
| 9 | DBG_TCK | 10 | 3V3 |
| 11 | GND | 12 | FLASH_CS0 |

* **JTAG**: TCK is the clock and TMS is mode select; the input/output directions of TDI and TDO are referenced to the main controller.
* **Flash**: MOSI is the data line from the host to the Flash, and MISO is the data line from the Flash to the host.
* **3V3**: Connects to the board 3.3 V power net.
